# Chapter 10: a Python LLM application

Python 3.10+; standard library only. Sources are fictional and fixture answers are authored, not generated by a model. Extract all files into one folder and open your terminal there.

## Run offline

```powershell
py app.py
py app.py --case transient --attempts 2
py app.py --case unsupported
py -m unittest -v test_app.py
```

Use your working `python` or `python3` instead of `py` when needed. An optional virtual environment can be created with `py -m venv .venv`; on Windows run `.venv\Scripts\python.exe app.py`.

Default mode makes no network calls, skips retry waits, and prints results without writing recommendation files. `review_required` means structure and source-ID membership passed; evidence still needs review. The unsupported fixture deliberately passes these checks with an unsupported ExampleFlix availability claim. This is a limitation demonstration, not verified output.

Cases: success, transient, authentication, refusal, incomplete, malformed, wrong_type, unknown_source, unsupported, invalid_input. `--attempts` permits 1 (default) or 2 TOTAL attempts. Only selected temporary provider failures are eligible for a retry. No retry repairs a refusal, truncated output, or invalid recommendation automatically.

`--input sources.json` reads a source array with exactly `id` and `text` fields. Supply 1-5 records, distinct S-number IDs, and 1-2000 characters of nonblank text per record. Offline fixture responses do not adapt to changed source content. CLI exit codes: 0 = candidate requires review; 1 = workflow stopped without candidate; 2 = setup/argument/file error. Printing a candidate does not save, send, or approve a recommendation.

## Optional live API mode

The adapter uses `https://api.openai.com/v1/responses`. You need API credentials, billing/access, and an accessible model supporting Responses with strict JSON-schema output. No model ID is assumed. Check your chosen model's capabilities and pricing before running. The live adapter was tested with fake HTTP responses; this edition did not make a live call or measure model quality.

Set `OPENAI_API_KEY` and `OPENAI_MODEL` in the process environment. For PowerShell 7, masked entry avoids putting the key into a command literal:

```powershell
$env:OPENAI_API_KEY = Read-Host "API key" -MaskInput
$env:OPENAI_MODEL = Read-Host "Model ID with Responses and Structured Outputs support"
py app.py --live --input sources.json
Remove-Item Env:OPENAI_API_KEY
```

Use a suitable secret manager or masked input mechanism on other shells. Never commit credentials or enter them in the handbook browser. The explicit live command transmits the supplied sources and can incur charges. Begin with the included fictional data. `store: false` is requested but is not a guarantee of zero retention. Check the provider's data controls for any real records.

The adapter uses a 30-second network-operation timeout, not a strict end-to-end deadline. It defaults to one attempt. An explicit second attempt can repeat processing/charges if the first timed out after reaching the service. Selected 5xx errors, connection failures, and recognized transient 429 codes can retry. Unknown/quota 429s stop. Numeric Retry-After values up to 10 seconds are honored; longer or date-form/invalid values stop for later caller handling. There is no unbounded retry, jitter sequence, SDK retry layer, streaming, persistent memory, or automatic external action.

## Explore the code

1. `validate_sources` rejects invalid local input before calling a provider.
2. `build_request` keeps instructions separate from serialized records and supplies a strict schema.
3. `provider.generate` obtains an envelope from a fixture or explicit live HTTPS call.
4. `extract_text` inspects completion/refusal and walks message items, skipping reasoning items.
5. `load_json` rejects malformed JSON, duplicate keys, and nonstandard numbers.
6. `validate_recommendation` checks fields, types, and evidence-ID membership.
7. `run_recommender` returns a candidate only with `review_required`.

The app does not verify claim support, citation coverage, or completeness. Compare each claim with the sources. The trace records app stages, not model reasoning. Source bodies/credentials are excluded from trace events; printed candidates can still contain sensitive data if you supply it. No raw error body is logged.

Tests use a dummy key and fake transport. They check application behavior and HTTP request construction, not service availability or live output quality. The website's trace is recorded from these fixture runs. Production work needs live integration checks, task evals, broader resource limits, access controls, and observability suited to its use.

Official references: [Responses](https://developers.openai.com/api/reference/python/resources/responses/methods/create), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [error codes](https://developers.openai.com/api/docs/guides/error-codes).
