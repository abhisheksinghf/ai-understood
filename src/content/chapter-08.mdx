## 1. Measure how fast a function changes

For f(x) = x², increasing x from 3 to 4 changes the output from 9 to 16. The **average rate of change** is (16 − 9) / (4 − 3) = 7. This is the slope of the line joining the two points, called a **secant**.

For a smaller change from 3 to 3.1, the slope is (9.61 − 9) / 0.1 = 6.1. Shrink the change further and this slope approaches 6. The **derivative** f′(3) = 6 describes the instantaneous rate at x = 3: the slope of the **tangent** there.

$$
f'(x)=\lim_{h\to0}\frac{f(x+h)-f(x)}{h}
\qquad\text{so for }f(x)=x^2,\quad f'(x)=2x
$$

A **limit** describes what a quantity approaches. We approach h = 0; we do not substitute zero into a division by h. For x², expanding the numerator gives 2xh + h², so the quotient is 2x + h, approaching 2x.

<CalculusDiagrams kind="slope" />

A positive derivative means increasing x slightly increases f locally; a negative derivative means it decreases f. A zero derivative means zero first-order slope, not necessarily a minimum. For a small change Δx, the local approximation is **Δf ≈ f′(x)Δx**. At x = 3, Δx = 0.1 predicts a change of 0.6; the exact change is 0.61. The approximation need not work for a large move.

Derivative units are output units divided by input units. When differentiating loss with respect to a weight, the question is how loss changes as that weight changes—not how the input itself changes. [D2L's calculus introduction](https://d2l.ai/chapter_preliminaries/calculus.html) provides further derivations.

<details className="optional-depth">
<summary>Go deeper: derivative rules and points without a derivative</summary>

For a constant c, d(c)/dx = 0. For a positive integer n, d(xⁿ)/dx = nxⁿ⁻¹. Derivatives distribute over sums and constant scaling: d(3x² + 2x + 7)/dx = 6x + 2. Two other useful rules are d(eˣ)/dx = eˣ and d(ln x)/dx = 1/x for x > 0.

The **product rule** is (uv)′ = u′v + uv′, not u′v′. The **quotient rule** is (u/v)′ = (u′v − uv′)/v² where v is nonzero. The chain rule, introduced below, handles one function inside another.

A function is **continuous** at a point when its nearby values approach its value there. Differentiability implies continuity, but continuity does not imply differentiability. The absolute-value function |x| is continuous at zero but has slopes −1 and +1 on its two sides, so no ordinary derivative there. ReLU, max(0, x), also has a kink at zero. Optimization libraries use specified conventions at such points; later neural-network chapters explain how these functions are used.

</details>

## 2. Move from one derivative to a gradient

A model usually has many parameters. A **partial derivative** changes one variable while holding the others fixed. A **gradient** collects those partial derivatives into a vector, in a stated order.

Use one dimensionless training example: input x = 2, target y = 5, prediction ŷ = wx + b. With w = 1 and b = 1, the prediction is 3. The **residual** r = ŷ − y is −2, and the half-squared loss is L = r²/2 = 2. The factor 1/2 simplifies the derivative without changing where the minimum occurs.

$$
\frac{\partial L}{\partial w}=(wx+b-y)x=-4,\qquad
\frac{\partial L}{\partial b}=wx+b-y=-2
$$

Thus **∇L = [−4, −2]** in [w, b] order. The symbol ∂ marks a partial derivative; ∇ is read “gradient” or “nabla.” These numbers describe two different sensitivities at the current parameters. They are not replacement parameter values.

For a differentiable scalar function, the gradient points toward steepest local increase measured using ordinary Euclidean distance in the chosen coordinates. Its negative points toward steepest local decrease. This is local information; the shape farther away and the step length still matter.

<details className="optional-depth">
<summary>Go deeper: Jacobians and Hessians connect to Chapter 6</summary>

A **Jacobian** is a matrix of first partial derivatives when a function has multiple outputs. Its row i and column j describe how output i changes with input j. For a scalar loss, the gradient is commonly written as a column vector; the Jacobian of that scalar output is its transpose under this convention.

A **Hessian** collects second partial derivatives of a scalar function into a matrix. It describes local curvature. For L(w) = (w − 3)²/2, the second derivative is 1 everywhere. For a smooth multivariable function, positive-definite curvature at a stationary point implies a strict local minimum; mixed positive and negative curvature indicates a saddle. A zero or singular Hessian can require further analysis.

</details>

## 3. Follow the chain rule through a calculation

The **chain rule** connects local rates along a composition. If a change in w changes a prediction, which changes a residual, which changes a loss, multiply the sensitivities along that path.

Hold x = 2, b = 1, and y = 5 fixed. Define p = 2w + 1, r = p − 5, and L = r²/2. At w = 1, the forward calculation gives p = 3, r = −2, and L = 2.

$$
\frac{dL}{dw}=\frac{dL}{dr}\frac{dr}{dp}\frac{dp}{dw}
=(-2)(1)(2)=-4
$$

<CalculusDiagrams kind="chain" />

The loss changes by approximately −4Δw for a small change to w at this point. If a parameter affects a loss through several paths, add the contributions from all those paths.

**Automatic differentiation** evaluates derivatives by applying differentiation rules to the operations in a computation. **Backpropagation** is the reverse-mode application used to efficiently obtain gradients of a scalar loss with respect to many parameters. The forward pass calculates values; the backward pass propagates sensitivities. An **optimizer** then uses those gradients to update parameters. Computing gradients alone does not change the parameters. See [D2L's automatic differentiation explanation](https://d2l.ai/chapter_preliminaries/autograd.html).

<details className="optional-depth">
<summary>Go deeper: numerical differentiation and a gradient check</summary>

A **finite difference** estimates a derivative by evaluating nearby inputs. A central difference uses [f(w + h) − f(w − h)] / (2h). It is useful for checking an implemented gradient on a small, smooth example, but requires extra function evaluations and can suffer from approximation and floating-point rounding errors. An arbitrarily tiny h is not always better.

Automatic differentiation applies the chain rule to executed operations, with ordinary floating-point precision; it does not estimate every derivative by perturbing every weight. **Symbolic differentiation** instead manipulates expressions to produce derivative formulas. These are three different approaches.

Detaching a value from a framework's calculation graph prevents gradients from following that connection. Whether a gradient should flow is part of the model design; it is not fixed by changing the learning rate. We will use framework autograd directly in the neural-network chapters.

</details>

## 4. Take a controlled step downhill

**Gradient descent** subtracts the gradient times a positive **learning rate** η (“eta”). For a parameter vector θ (“theta”), all gradient components are evaluated at the current parameters before updating:

$$
\boldsymbol{\theta}_{t+1}=\boldsymbol{\theta}_t-\eta\nabla L(\boldsymbol{\theta}_t)
$$

The subscript t counts updates. The learning rate controls the size of a move; it is a chosen **hyperparameter**, distinct from the fitted parameters θ.

For the experiment below, switch to the simpler, dimensionless objective **L(w) = (w − 3)²/2**, whose derivative is w − 3. This is a separate teaching function, not the previous training example or Chapter 3's runtime dataset. Starting at w = 0 with η = 0.5:

**gradient = −3 → new w = 0 − 0.5(−3) = 1.5 → new loss = 1.125**, down from 4.5.

<DescentLab client:load />

Try η = 0.5, then 1.5, then 2 and 2.2, starting at zero each time. Crossing the minimum does not automatically mean failure: at 1.5 the iterates alternate sides but get closer. At 2 they cycle; at 2.2 they move farther away. The [gradient-descent chapter in D2L](https://d2l.ai/chapter_optimization/gd.html) develops the role of the step size.

<details className="optional-depth">
<summary>Go deeper: why these particular learning rates behave differently</summary>

For this quadratic, subtracting the optimum 3 from both sides of the update gives wₜ₊₁ − 3 = (1 − η)(wₜ − 3). Each update multiplies the error by 1 − η. Starting away from the minimum, convergence occurs when |1 − η| is less than 1: **0 < η < 2**. At η = 1, the error becomes zero in one step. At η = 2, it changes sign but keeps its magnitude.

This range belongs to this objective's curvature; it is not a universal safe range for neural networks. Multiplying the loss by 100 multiplies the gradient by 100, changing suitable step sizes. If you start exactly at w = 3, the gradient is zero and every displayed rate leaves it there.

</details>

## 5. Understand what an optimizer can and cannot solve

A **global minimum** is best over the allowed domain; a **local minimum** is best within a neighborhood. A **stationary point** has zero gradient, but might be a minimum, maximum, or saddle. For f(x) = −x², the zero slope at zero is a maximum. For f(x, y) = x² − y², the origin is a saddle: moving one way increases the value and another decreases it.

A **convex** function lies below or on the straight segment joining any two points on its graph over a convex domain. For convex objectives, every local minimum is global. Neural-network objectives are generally nonconvex; a low training loss does not certify a global optimum or good performance on new data.

| Update method | Data used for a gradient | Trade-off |
|---|---|---|
| Full-batch gradient descent | Entire training set | Exact gradient of that dataset's average loss; expensive per update |
| Stochastic gradient descent (SGD) | One sampled example in the strict definition | Cheap, noisy updates |
| Mini-batch gradient descent | A sampled group of examples | Common compromise; often also called SGD |

An **epoch** is one pass through a training set; a **step** is one parameter update. With 1,000 examples, batch size 100, no dropped examples, and one pass, there are 10 updates. Training mini-batches are usually shuffled; dependence, sampling choices, and batch size influence gradient noise.

<details className="optional-depth">
<summary>Go deeper: momentum, Adam, regularization, and stopping</summary>

**Momentum** combines current and past gradients in a running update direction, which can reduce some oscillation and accelerate progress. **Adam** maintains moving averages of gradients and squared gradients, applies bias corrections, and scales updates by coordinate. It still has a learning rate and can fail with poor settings; it does not guarantee a global minimum. Learning-rate **schedules** vary the rate over training.

**Regularization** adds preferences or constraints to fitting. A common objective is average data loss plus λ times a penalty; λ controls the penalty strength. An L2 penalty proportional to the sum of squared weights favors smaller weights, but its exact coefficient convention determines its gradient. Regularization changes what is being optimized, not merely how quickly it is optimized.

**Early stopping** chooses when to stop using validation behavior, keeping the test set for final evaluation. Stopping can also involve an update budget or convergence criterion. A tiny gradient alone can reflect flatness or numerical trouble, and decreasing training loss does not prove generalization. We will study optimizer choices and training diagnostics in later chapters.

</details>

## 6. Use integration to accumulate small contributions

Differentiation describes a local rate; **integration** accumulates contributions over an interval. A definite integral is the limit of sums of thin slices. For positive values, it can be read as area under a curve; negative parts contribute signed area.

$$
\int_0^3 2t\,dt=[t^2]_0^3=3^2-0^2=9
$$

The integral symbol ∫ means accumulate, 0 and 3 are the limits, and dt names the variable of integration. Here t² is an **antiderivative** of 2t because its derivative is 2t. The fundamental theorem of calculus connects these two operations: under suitable continuity conditions, evaluate an antiderivative at the upper endpoint and subtract its value at the lower endpoint.

This gives meaning to Chapter 7's continuous probability density. Suppose a toy duration T is uniformly distributed between 0 and 0.5 seconds. Its density is 2 per second inside that interval and zero outside. Probability between 0.1 and 0.3 seconds is **2 × (0.3 − 0.1) = 0.4**. Total area is 2 × 0.5 = 1. Density height 2 is valid because probability comes from an area, not the height alone.

For a continuous variable with density p(t), a cumulative probability is an integral of p, and an expectation accumulates t p(t). These are the continuous counterparts of adding probabilities and probability-weighted values. Integration also appears when averaging over uncertain quantities; practical methods may use numerical approximation or sampling.

## 7. Measure surprise and average uncertainty

In information theory, **self-information**, or surprisal, of an outcome with probability p is **−log₂ p**. A rare outcome carries more information under that distribution. This is a mathematical measure of surprise, not a measure of truth, usefulness, or human understanding.

| Probability of the observed outcome | Surprisal |
|---|---:|
| 1 | 0 bits |
| 1/2 | 1 bit |
| 1/8 | 3 bits |

Using base-2 logarithms gives **bits**; using natural logarithms gives **nats**. The logarithm turns products into sums, so surprise adds for independent outcomes. An outcome assigned probability zero has infinite surprisal if it occurs.

**Entropy** is the expected surprisal of a distribution. For a toy job outcome with probabilities P(healthy) = 0.75 and P(failed) = 0.25:

$$
H(P)=-\sum_i p_i\log_2 p_i
=-0.75\log_2(0.75)-0.25\log_2(0.25)
\approx0.8113\text{ bits}
$$

<CalculusDiagrams kind="entropy" />

The sum runs over possible categories. A fair binary outcome has entropy 1 bit; a certain outcome has entropy 0. For k categories, the maximum is log₂ k, achieved by a uniform distribution. We use the limiting convention 0 log 0 = 0 in the entropy sum; this does not mean log 0 itself is finite.

Entropy characterizes uncertainty under a distribution. A model can be very certain and wrong: low predicted entropy is not proof that its prediction is reliable.

## 8. Compare a predicted distribution with a target

**Cross-entropy** scores predicted probabilities Q using a target distribution P. Keep the same category order. For P = [0.75, 0.25] and the uniform prediction Q = [0.5, 0.5]:

$$
H(P,Q)=-\sum_i p_i\log_2 q_i
=-0.75\log_2(0.5)-0.25\log_2(0.5)=1\text{ bit}
$$

Entropy uses P both for the weights and inside the logarithm. Cross-entropy keeps P as the weights but uses the prediction Q inside the logarithm. That change is the whole distinction.

**Kullback–Leibler (KL) divergence** measures the excess cross-entropy over the entropy of P:

$$
D_{\mathrm{KL}}(P\Vert Q)=H(P,Q)-H(P)
=1-0.811278\approx0.188722\text{ bits}
$$

For valid discrete distributions, KL is nonnegative and zero exactly when they match. It is generally asymmetric and is not a mathematical distance metric. Holding P fixed, minimizing cross-entropy also minimizes KL because H(P) does not depend on Q. See [D2L's information-theory chapter](https://d2l.ai/chapter_appendix-mathematics-for-deep-learning/information-theory.html) for the coding interpretation and derivations.

In supervised classification, one observed label is commonly represented by a **one-hot target**: 1 for the observed category and 0 for the others. Cross-entropy then reduces to the negative log of the probability assigned to that category. Using natural logs, a true-category probability of 0.8 gives **−ln(0.8) ≈ 0.2231 nats**; probability 0.2 gives **1.6094 nats**. Confident mistakes are penalized more strongly.

<details className="optional-depth">
<summary>Go deeper: likelihood, zero probabilities, and mutual information</summary>

Under a model that treats labeled examples as conditionally independent given inputs and parameters, the dataset likelihood is a product of assigned label probabilities. Taking its negative log turns that product into a sum of losses. Minimizing this **negative log-likelihood (NLL)** is equivalent to maximum likelihood under those assumptions. Averaging instead of summing changes the scale, not the minimizer for a fixed dataset.

If pᵢ > 0 but qᵢ = 0, cross-entropy and KL are infinite. Terms with pᵢ = 0 contribute zero by convention. Code may use clipping or stable formulas, but clipping changes the exact objective near the boundaries; it is not a mathematical identity.

**Conditional entropy** H(Y | X) is the average uncertainty about Y after X is known. **Mutual information** I(X; Y) = H(Y) − H(Y | X) measures the reduction in uncertainty for discrete variables with finite entropies. It can detect dependence beyond linear correlation, but dependence alone does not establish causality. These quantities support later topics such as feature selection and representation learning.

</details>

## 9. Connect a probability loss to a parameter update

A binary classifier can turn a real-valued score z, called a **logit**, into a probability with the **sigmoid** q = 1/(1 + e⁻ᶻ). Let y be the observed label, 0 or 1. Binary cross-entropy using natural logs is:

$$
L=-[y\ln q+(1-y)\ln(1-q)],\qquad \frac{dL}{dz}=q-y
$$

The derivative follows by chaining the loss derivative through the sigmoid: dL/dq = −y/q + (1 − y)/(1 − q), and dq/dz = q(1 − q). Multiplying and simplifying gives q − y, for finite z and hence 0 < q < 1.

If y = 1 and q = 0.8, dL/dz = −0.2. A small descent step on z increases z, which increases q and reduces this example's loss. If z = wx + b, apply the chain rule again: ∂L/∂w = (q − y)x. In actual training the parameters w and b are updated, not an independently stored probability for each example.

This is the connection: choose a probability model, define a loss, differentiate it, then use an optimizer. For multiple classes, **softmax** converts a vector of logits into positive probabilities summing to one by exponentiating and normalizing. The classification and neural-network chapters develop these models and their numerically stable implementations.

Reproduce the simple quadratic update with ordinary Python:

```python
w = 0.0
learning_rate = 0.5
for step in range(1, 4):
    gradient = w - 3
    w -= learning_rate * gradient
    loss = 0.5 * (w - 3) ** 2
    print(step, w, loss)
# 1 1.5 1.125
# 2 2.25 0.28125
# 3 2.625 0.0703125
```
